# fairino_mpc_avoidance 包详细说明

本文档用于说明 `fairino_mpc_avoidance` 包内各文件的职责、模块关系和运行数据流，便于后续调参、维护和二次开发。

---

## 1. 包整体目标

`fairino_mpc_avoidance` 提供一套面向机械臂的 **MPC 实时避障与轨迹跟踪** 实现，包含三条可独立构建的链路：

1. `runtime_core`：在线控制主链（MPC 节点、求解器、控制编排、障碍物跟踪、可视化）
2. `moveit_plugin`：MoveIt 规划插件链（可选）
3. `sim_tools`：仿真与演示工具链（可选）

外部兼容目标：
- 保持 ROS 话题/状态接口稳定
- 保持 acados OCP 生成链稳定
- 参数统一在 YAML 中可配置

## 2. 目录与文件职责

## 2.1 根目录构建与元信息

- `CMakeLists.txt`  
  包构建入口。定义三条源码集合（core/plugin/sim）、可选开关、acados 生成依赖、目标安装规则。

- `package.xml`  
  ROS 依赖清单与包元信息。

- `setup_acados_env.sh`  
  配置 `ACADOS_INSTALL_DIR` 等环境变量，供代码生成与编译使用。

---

## 2.2 配置目录 `config/`

- `mpc_params.yaml`  
  **MPC 主参数源**。控制周期、权重、APF/CBF、死锁与重规划、输出平滑与限幅、关节映射等统一在此配置。

- `obstacle_stack.yaml`  
  **障碍物场景统一配置源**。静态/动态障碍物几何、边界、速度、spawn 信息统一定义；`mpc_avoidance_node` 与 `obstacle_simulator` 共用。

- `static_mid_wall.urdf`  
  静态中墙模型资源。

---

## 2.3 头文件目录 `include/fairino_mpc_avoidance/`

### 基础与参数

- `types.hpp`  
  核心类型定义（`VecN`、`Obstacle`、`RefWindow` 等）。

- `mpc_solver.hpp`  
  `MPCParams` 结构、`MPCSolver` 公共接口定义。

- `mpc_params_loader.hpp`  
  参数声明与加载器，负责将 ROS 参数/YAML 映射到 `MPCParams`。

- `mpc_solve_context.hpp`  
  求解上下文（`MPCSolveContext`），封装 `solve()` 输入，避免长参数列表。

### 几何/距离/动力学辅助

- `robot_kinematics.hpp`  
  机械臂正运动学与采样接口。

- `smooth_box_distance.hpp`  
  点到盒障碍物的光滑距离计算。

- `obstacle_distance_ops.hpp`  
  统一 APF 与距离操作：`minMargin` / `apfValue` / `apfGradient`。

- `obstacle_tracker.hpp`  
  障碍物跟踪与未来预测接口。

- `arc_path_follower.hpp`  
  弧长路径管理、窗口参考提取、进度推进接口。

- `scenario_loader.hpp`  
  场景 YAML 加载器；统一 `scenario_config` 解析路径与场景一致性校验。

- `rviz_visualizer.hpp`  
  RViz 可视化发布接口（全局路径、实时参考、EE 轨迹等）。

### 控制域 `control/`

- `control/control_coordinator.hpp`  
  控制周期阶段协调器，固定执行顺序：`precheck -> plan -> publish -> deadlock_eval -> finalize`。

- `control/command_pipeline.hpp`  
  输出指令管道：平滑、限幅、hold/brake、横向避障 bias 辅助。

- `control/deadlock_replan_engine.hpp`  
  死锁检测与重规划触发逻辑引擎。

- `control/scene_obstacle_provider.hpp`  
  从 MoveIt PlanningScene 提取静态障碍物。

### 运行时状态域 `runtime/`

- `runtime/runtime_state.hpp`  
  控制周期共享状态结构体（纯数据）。

- `runtime/mpc_runtime_state.hpp`  
  线程安全状态持有器（`snapshot/mutate/update...`），是运行时状态唯一入口。

### 插件域 `plugin/`（可选）

- `plugin/moveit_integration.hpp`  
  MoveIt 集成辅助，封装规划上下文与结果转换。

- `plugin/mpc_planner_manager.hpp`  
  MoveIt `PlannerManager` 插件入口（插件名 `MPC_Avoidance`）。

## 2.4 源码目录 `src/`

### 主节点与求解核心

- `mpc_avoidance_node.cpp`  
  主节点。负责 ROS I/O、周期驱动、协调器回调绑定、状态快照回写、话题发布。

- `mpc_solver.cpp`  
  acados OCP 封装与求解流程（参数写入、warm start、APF/CBF参数构建、求解统计）。

### 算法与工具实现

- `arc_path_follower.cpp`
- `obstacle_tracker.cpp`
- `obstacle_distance_ops.cpp`
- `robot_kinematics.cpp`
- `smooth_box_distance.cpp`
- `rviz_visualizer.cpp`  
  分别对应上述头文件的实现。

### 控制域实现 `src/control/`

- `control_coordinator.cpp`：阶段调度与输出汇总
- `command_pipeline.cpp`：控制指令后处理
- `deadlock_replan_engine.cpp`：停滞/死锁判定与重规划触发
- `scene_obstacle_provider.cpp`：场景障碍物提取

### 运行时状态实现 `src/runtime/`

- `mpc_runtime_state.cpp`：状态快照和线程安全更新实现

### 插件实现 `src/plugin/`（可选）

- `moveit_integration.cpp`
- `mpc_planner_manager.cpp`

### 仿真工具 `src/sim/`

- `obstacle_simulator.cpp`  
  动态障碍物运动与发布节点，读取 `obstacle_stack.yaml`。

## 2.6 acados 生成目录 `c_generated_code/`

该目录包含 acados 自动生成源码（模型、代价、约束、solver 封装）。  
特点：
- 由脚本生成，不建议手改业务逻辑
- 编译强依赖
- 版本更新时需与 `scripts/generate_acados_solver.py` 同步

## 3. 核心模块关系（调用链）

1. `mpc_avoidance_node` 定时进入控制周期  
2. 通过 `MpcRuntimeState::snapshot()` 获取状态  
3. `ControlCoordinator` 分阶段调用节点回调：
   - precheck：状态合法性/冷却/settling 判定
   - plan：障碍物收集 + 参考窗口 + `MPCSolver::solve`
   - publish：`CommandPipeline` 平滑限幅并发布控制
   - deadlock_eval：`DeadlockReplanEngine` 判定重规划
   - finalize：目标判定与日志
4. `ControlCycleOutput::applyTo(RuntimeState&)` 回写状态
5. 可视化由 `RVizVisualizer` 周期发布

---

## 4. 参数与场景统一原则

- 动态避障核心参数统一放在 `config/mpc_params.yaml`
- 场景统一放在 `config/obstacle_stack.yaml`
- `ScenarioLoader::resolvePath()` 统一解析 `scenario_config`
- `mpc_avoidance_node` 与 `obstacle_simulator` 共用同一场景配置路径逻辑

---

## 5. 哪些文件通常不要改

- `c_generated_code/*`：自动生成代码，除非明确重生成流程
- `scripts/acados_ocp_fairino_mpc.json`：改它通常意味着模型层变化

---

## 6. 常见开发入口建议

1. 调参优先改：`config/mpc_params.yaml`
2. 改场景优先改：`config/obstacle_stack.yaml`
3. 调控制逻辑优先看：  
   - `src/mpc_avoidance_node.cpp`
   - `src/control/command_pipeline.cpp`
   - `src/control/deadlock_replan_engine.cpp`
4. 调求解行为优先看：`src/mpc_solver.cpp`

---

## 7. 版本维护建议

- 每次新增影响行为的阈值，优先进入 `MPCParams` + Loader + YAML
- 保持日志关键词兼容（`[MPC] [CTRL] [OBS-CB] Replan triggered MPC-STATS`）
- 重要重构后同步更新本文档，避免“代码/文档漂移”

---

## 8. NMPC 扩展落点

当前包已经把“求解输入”和“控制外壳”拆开，后续加 NMPC 时按下面落点扩展即可，不需要先引入空基类：

- 复用输入层：继续使用 `MPCSolveContext`、`Obstacle`、`RefWindow`
- 复用公共几何层：`ObstacleDistanceOps`、`RobotKinematics`、`ArcPathFollower`
- 保留当前 `MPCSolver` 作为 acados MPC 实现；新增 `NmpcSolver` 即可
- 运行入口保持一个控制节点，只增加 `solver_type:=mpc|nmpc` 选择
- 若 NMPC 也走代码生成，生成物单独放到 `c_generated_code_nmpc/`，不要和现有 MPC 生成物混放

这样做的目的很简单：公共层只放“避障问题本身”，求解器层只放“具体优化器实现”。

## 9. 模型切换最小操作（新增）

`mpc_planning_demo.launch.py` 已支持通过 `robot_profile` 自动切换 MoveIt 配置、规划组、末端 link、关节名和控制器话题。

### 8.1 常用启动方式

Fairino Arm（带夹爪）：

```bash
ros2 launch fairino_mpc_avoidance mpc_planning_demo.launch.py robot_profile:=fairino_arm_gripper planning_client:=fairino planner_id:='birrt*'
```

Fairino3_v6（无夹爪）：

```bash
ros2 launch fairino_mpc_avoidance mpc_planning_demo.launch.py robot_profile:=fairino3_v6 planning_client:=fairino planner_id:='birrt*'
```

可选显式覆盖规划命名空间：

```bash
ros2 launch fairino_mpc_avoidance mpc_planning_demo.launch.py robot_profile:=fairino3_v6 planning_move_group_namespace:=/move_group_fairino planner_id:='birrt*'
```

### 8.2 参数来源与注入路径

`robot_profile` -> `gazebo_launch/config/robots/<profile>.yaml` -> 自动注入：

- `MoveItConfigsBuilder(moveit_config_name, package_name=moveit_config_package)`
- `group_name`（例如 `robot_arm` / `fairino3_v6_group`）
- `ee_link`（例如 `grasp_frame` / `wrist3_link`）
- `base_frame`
- `joint_names`
- `controller_topic = <arm_controller>/joint_trajectory`

### 8.3 防呆与错误定位

- `demo_mpc_avoidance_node.py` 启动时会解析 `robot_description_semantic`，校验 `group_name` 是否存在于 SRDF。
- 若组名错误（如 `fairino3_v6_robot`），会立即失败并打印可选组名列表，避免运行中才报 `Joint model group not found`。


## TF / PlanningScene frame 注意事项

`mpc_planning_demo.launch.py` 不发布 `world -> map` 或 `world -> viewer` 静态 TF。若 MoveIt 日志出现 `viewer/map` 无法转换到 `world`，优先检查 RViz 或外部 PlanningScene/CollisionObject 发布源，把对象 frame 改为 `world` 或 `base_link`。只有确认 `map` 与 `world` 同原点且语义一致时，才应显式添加静态 TF。
